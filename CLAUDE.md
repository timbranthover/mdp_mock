# MDP Digital Twin — working rules

This repo is a desktop-only digital twin of the UBS Model Delivery Portal (Money Manager view), used to mock up features with the MDP product team. All data is mock.

## Domain context
- These are **SMA investment models**: one model = a set of target **weights** (%) that is traded across many client accounts. Everything is expressed in weights. Never add share counts, quantities, market values or dollar amounts to model editing or import. They don't apply to a model.
- USD Cash is the residual that keeps a model at 100%.
- **UBS Building Blocks** are ordinary models (manager `UBS CIO Building Blocks`, B3xx), each like one SMA.
- **Portfolios** (`js/portfolios.js`, `parent: true`, `family: 'myway' | 'mm'`): UBS CIO parent models. MyWay Portfolios (W2xx) hold UBS Building Blocks only; Multi-Manager Portfolios (M1xx) hold third-party SMAs only. Consolidated weight = SUM(allocation × security weight). One level only, no mixing. Third-party managers never see portfolios (persona views filter them out). Approving any underlying model auto-recalculates every portfolio using it.
- Curated holdings live in `CURATED` (data.js): blocks B301–B308 and the third-party models used in Multi-Manager Portfolios (modelled on public fact sheets). New securities go in `growth2`/`value2` so the random pools (and the import test pack built on N529) don't shift.

- **After Submit** (`js/uma.js`): impact strip, Delivery tab and dashboard, Accounts, Guardrails, cross-sleeve conflicts, Fees. Deliveries are **derived from audit events** (`Model Approved`, `Portfolio Approved`, `Underlying Model Updated`) and accounts are **generated by index**; do not add stored records for them. Dollar amounts are fine in Fees and AUM, never in model editing.
- **Trading window**: 9:30–15:45 ET on business days. All stamps are New York wall-clock strings.
- **Seed dates** are shifted forward in whole weeks (`shiftDays` in data.js) so mock activity is always recent. Write new seed dates around late Oct / early Nov 2026 and let the shift move them.
- **Persistence** stores only models whose signature differs from the seed (`sigOf` in app.js). If a new kind of edit does not add an audit event, bump `m.rev` so it is saved.
- **External managers** (persona views) must never see portfolios, accounts, fees or anything derived from them.
- **Walkthrough** (`js/tour.js`): when a screen it points at changes, update its step (selector, wording). No sales language: state what production does and what differs.

## Always keep the Improvements log current
`js/improvements.js` lists everything that is **net new vs. the production app** (shown in-app at `#/improvements`, exportable to Excel).

- When you add or change a feature that production does not have, add or update an entry: `id` (area prefix + number), `area`, `title`, `today` (production behavior), `change` (what the twin does), `why`, `added` (YYYY-MM-DD), `status`, and `try` (a hash route to demo it, optional; append `?import` to open the Import panel).
- Fidelity fixes that only make the twin match production are **not** improvements. Don't log them.
- When a feature is removed, remove its entry.

## Conventions
- Plain HTML/CSS/JS, no build step, no CDN dependencies (users are on locked-down Citrix desktops). Excel I/O is `js/xlsx.js`.
- Bump the `?v=` query on script/style tags in `index.html` whenever JS/CSS changes (assets are cached as immutable).
- New UI must fit the existing visual style (square corners, tan/black buttons, banner `#5A5D5C`, small caps labels).
- `?ux=current` shows production behavior where the twin proposes a change; `?reset=1` restores seed data; `?persona=blackrock` shows the single-manager view.
